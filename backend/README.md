# Обучение SilentAC: первая проверяемая модель

Этот модуль обучает базовую логистическую модель для **aim/rotation**, а не универсальный детектор всех читов. Нейросеть, готовый датасет и подтверждённое качество здесь не поставляются. Сначала собирайте данные на контролируемом тестовом Paper 1.21.4 сервере с ProtocolLib. Участники должны знать о записи; UUID в файлах — идентификаторы игроков, не публикуйте сырые записи и ключи.

## Установка и безопасный запуск

Из любой папки, где вы хотите разместить проект:

```bash
git clone https://github.com/MigosHack/AnGuard.git
cd AnGuard
bash start-backend.sh
```

Если изменения пока находятся в ветке `work`, клонируйте с `git clone -b work https://github.com/MigosHack/AnGuard.git`.

Один скрипт создаёт `backend/.venv`, устанавливает закреплённые зависимости и запускает API. На Debian/Ubuntu при отсутствии Python/venv он устанавливает их через apt (нужны root или sudo); если системный Python несовместим (например, Ubuntu с Python 3.14), скрипт скачивает отдельный Python 3.12 через закреплённый uv в `backend/.local/`, не меняя системный Python. Для загрузки нужны доступ к PyPI и GitHub. На других системах требуется установленный Python с venv для первоначального запуска. Для самого бэкенда Java не нужна. Повторный запуск переиспользует окружение и ключ. Путь к проекту может быть любым, включая пробелы; скрипт можно вызывать из другой директории. Для остановки нажмите Ctrl+C.

```bash
bash start-backend.sh --port 8000
bash start-backend.sh --model backend/models/aim-v2.json
bash start-backend.sh --install-only
bash start-backend.sh --test
```

Без `--model` API запускается без модели: это позволяет подготовить сервер до сбора данных, но предсказания ещё недоступны. Пути к модели и данным задаются относительно текущей папки shell. Если порт занят, выберите другой через `--port` и измените `vds.port` плагина.

Сервер слушает только loopback:8000. `local.py` создаёт случайный ключ с правами 0600 в игнорируемом `backend/.local/api-key`; не выводит его. При заданном `SILENTAC_API_KEY` использует его вместо локального файла. Не используйте публичный ключ из старого config.yml.

Перед запуском Minecraft задайте **тот же** ключ в окружении процесса Java. Например, для локально созданного ключа в shell, из корня репозитория:

```bash
export SILENTAC_API_KEY="$(cat backend/.local/api-key)"
# Затем запустите свой Paper-сервер из этой shell с JDK 21.
```

Не включайте shell tracing (`set -x`) и не печатайте переменную. Разместите собранный `build/libs/SilentAC-3.0.jar` и `libs/ProtocolLib.jar` в каталоге plugins вашего Paper-сервера. Адрес API задаётся в **сгенерированном сервером** `plugins/SilentAC/config.yml`: `vds.ip: 127.0.0.1`, `vds.port: 8000`. Ключ из переменной окружения имеет приоритет перед `vds.secret_key`. Существующим установкам нужно явно добавить `ai.observe-only: true`, отключить `autoban.enable` и `ai.damage-reduction.enabled`; пакетные значения конфигурации не перезаписывают старый файл.

Plain HTTP поддерживается только на одной машине через loopback. Для удалённого API сначала требуется отдельная настройка TLS-транспорта; не пересылайте этот ключ по открытой сети.

`GET /health` без модели возвращает `status=ok, ready=false`. Запросы предсказания без модели получают 503, а не выдуманную оценку. Сервер предназначен для локальной разработки; пропускную способность под вашей нагрузкой нужно измерять отдельно.

## SilentAC: обновление и интерфейс записи

Соберите с JDK 21: `bash gradlew build`. Установите **`build/libs/SilentAC-3.0.jar`**, предварительно удалив старый JAR AnGuard из `plugins` на остановленном сервере. Не оставляйте два JAR одновременно. Публичное имя плагина и каталог данных теперь `SilentAC`, основная команда `/silentac`, алиасы `/anguard` и `/agac` сохраняются. Основные права: `silentac.admin` и `silentac.bypass`; старые `anguard.admin`/`anguard.bypass` поддерживаются как совместимые алиасы. Java namespace и бинарный протокол оставлены совместимыми; 48 признаков и модели schema=2 не меняются.

Если `plugins/SilentAC` ещё нет, при запуске весь каталог `plugins/AnGuard` переносится в `plugins/SilentAC`, включая записи и конфигурацию. Если оба каталога уже есть, они не объединяются и не перезаписываются; используется SilentAC, а старые файлы остаются на месте. Перед заменой JAR рекомендуется обычная резервная копия сервера. При первом обновлении старой конфигурации прежний файл сохраняется как `config-before-silentac.yml`, а раздел сообщений заменяется бело-серой темой с градиентами. Настройки API, модели, буфера и наказаний сохраняются. После применения `appearance.version: 1` пользовательские изменения сообщений больше не сбрасываются.

```text
/anguard recording start Steve 15:00
/anguard recording start Steve 15:00 cheat
/anguard recording start Steve
/anguard recording stop Steve
```

Без метки используется `recording.default-label: legit`; выбранная метка явно показывается в сообщении и actionbar. Для известных контролируемых cheat-сессий передавайте `cheat`, иначе данные будут неверно размечены. Старые `/anguard record Steve legit|cheat` и `/anguard stop Steve` продолжают работать.

Время: `15` означает **15 минут**, `15:00` — MM:SS; также поддерживаются `30s`, `15m`, `1h`. Диапазон: от 1 секунды до 24 часов. Без времени запись идёт до ручной остановки/выхода игрока, и боссбар не создаётся. При заданном времени игрок и администратор, начавший запись, видят **белый боссбар с overlay PROGRESS** и текстом `Осталось: 15:00`. Отсчёт использует монотонное реальное время; при истечении запись автоматически прекращается на ближайшем серверном тике. Повторный start заменяет предыдущую сессию, очищает её боссбар и начинает отдельную разметку.

При каждом неотменённом прямом ударе записываемого игрока actionbar показывает имя, количество ударов за сессию, число уже записанных окон, сэмплов и метку. Удары — счётчик событий попадания, не отдельные обучающие строки; отменённые события и снаряды не учитываются. Окна пишутся асинхронно, поэтому счётчик отражает уже завершённую запись на момент обновления; сэмплы считаются как `окна × 40` и могут перекрываться. Поле `hits` также сохраняется в новых JSONL как счётчик на момент принятия окна. Информационный трекер не перекрывает этот actionbar в течение двух секунд после удара. Боссбары убираются при остановке, выходе записываемого игрока и отключении плагина.

Переменная ключа теперь `SILENTAC_API_KEY`; прежняя `ANGUARD_API_KEY` по-прежнему поддерживается и плагином, и бэкендом. Если заданы обе, приоритет у `SILENTAC_API_KEY`. Не меняйте ключ только из-за переименования.

## Сбор данных

В игре или серверной консоли, с правом `silentac.admin`:

```text
/anguard recording start PlayerName 15:00 legit
/anguard recording stop PlayerName
/anguard recording start PlayerName 15:00 cheat
/anguard recording stop PlayerName
```

Метка задаётся администратором **по известным условиям эксперимента**, никогда по оценке модели. `cheat` записывайте только в изолированном тесте с заранее известным включённым aim-читом; `legit` — с проверенным чистым клиентом. Старт новой записи создаёт новую сессию и сбрасывает окно; выход игрока прекращает запись. Во время записи игрок не наказывается этой проверкой, даже если позже вы включите наказания.

Файлы: `plugins/SilentAC/training/windows-<uuid>.jsonl`. **Схема v2: 40 сэмплов × 48 чисел**, а не прежние 40 × 8. Сэмпл — изменение вращения, не гарантированно серверный тик. Хранятся UUID игрока/сессии, метка и время. Файловая запись вынесена в отдельный поток с ограниченной очередью; при переполнении окна отбрасываются с предупреждением. Следите за размером файлов и свободным местом, запись сама по таймеру не прекращается.

48 признаков каждого сэмпла (точный порядок: `backend/core.py`, `COLUMNS`):

| Позиции (с 1) | Признаки | Количество |
|---|---|---:|
| 1–8 | deltaYaw, deltaPitch, accelYaw, accelPitch, **jerkPitch, jerkYaw**, gcdErrorYaw, gcdErrorPitch | 8 |
| 9–17 | Модули delta/acceleration/jerk по yaw и pitch и евклидовы величины этих трёх пар | 9 |
| 18–19 | Нормированные компоненты направления вращения yaw/pitch | 2 |
| 20–21 | Смена знака вращения yaw/pitch относительно предыдущего сэмпла | 2 |
| 22–24 | Знаковые изменения deltaYaw/deltaPitch и изменение общей величины вращения | 3 |
| 25–48 | Среднее, стандартное отклонение, минимум, максимум по последним максимум 20 сэмплам для deltaYaw, deltaPitch, accelYaw, accelPitch, gcdErrorYaw, gcdErrorPitch | 24 |

Дополнительные признаки вычисляются из исходного вращения: это не независимые измерения reach, позиции или скорости бега. Нули в неподвижных/первых сэмплах обрабатываются без деления на ноль; скользящая статистика использует только текущие и прошлые сэмплы внутри окна. При перекрытии окон один и тот же сэмпл в их начале может иметь другой доступный контекст — это одинаково реализовано в Java и Python.

**Старые записи schema=1 с 8 колонками можно использовать:** обучение автоматически вычисляет все 48 признаков по тем же правилам. Новые записи schema=2 и API передают все 48. Их дополнительные значения проверяются на соответствие исходным восьми; простое дополнение нулями отклоняется. Старые восьмиколоночные бинарные запросы также поддерживаются.

**Старые модели schema=1 несовместимы и требуют переобучения.** Обновите плагин и бэкенд вместе. При обучении используйте новое имя файла, например `aim-v2.json`; прежнюю модель скрипт не перезаписывает. До обновления обоих компонентов держите режим наблюдения включённым.

Окна после телепорта исключаются; при ping >200 мс или TPS <18 запись и применение оценки пропускаются. Это базовые предохранители, не доказательство защиты от всех сетевых артефактов.

Соберите разные чувствительности мыши, FPS, стили PvP и уровни навыка, включая сильных честных игроков. Разделите тесты по типам и настройкам aim-читов. Не используйте один UUID для всех участников. Минимум инструмента — 15 разных игроков с обоими классами в каждой части; для достоверных выводов нужно значительно больше. Скопируйте файлы в игнорируемый `backend/recordings/`.

## CSV как в примере

При записи плагин по умолчанию создаёт рядом два файла с одинаковым именем: `.jsonl` (окно одной строкой) и `.csv` (сэмпл одной строкой). Это два представления одних данных; подавайте в обучение **только одно** из них, иначе защита от дублей отклонит вход. CSV увеличивает объём записи на диске. Отключение в серверном `plugins/SilentAC/config.yml` с последующим перезапуском:

```yaml
training:
  csv-enabled: false
```

CSV имеет заголовок и 55 колонок: `label`, 48 именованных признаков в порядке `COLUMNS`, затем `player_id,session_id,window_id,frame_index,timestamp_ms,schema`. `label=0` означает legit, `label=1` — cheat. Числа используют точку и сохраняют исходную точность float32 независимо от локали сервера; округление до фиксированного количества десятичных знаков не применяется. Один window_id содержит ровно 40 последовательных строк с frame_index от 0 до 39. Идентификаторы сохраняются для разделения по игрокам и восстановления последовательностей. Простые CSV без заголовка и идентификаторов, как отдельная строка на скрине, не дают корректно восстановить эти границы и не принимаются.

Обучение напрямую из CSV:

```bash
bash start-backend.sh --train backend/recordings/*.csv --output backend/models/aim-csv-v1.json
```

Неполные окна (например, при аварийном завершении записи), повторные индексы, смена метки/игрока внутри окна, неверные заголовки и противоречивые дополнительные признаки отклоняются с указанием файла и строки. CSV формат не меняет 48 признаков или модель schema=2; существующие JSONL по-прежнему поддерживаются.

## Обучение и проверка

```bash
bash start-backend.sh --train \
  backend/recordings/*.jsonl --output backend/models/aim-v2.json \
  --target-fpr 0.001
```

Игроки делятся 60/20/20 на обучение, калибровку порога и финальную проверку. Ни один UUID не попадает в разные части, поэтому перекрывающиеся окна одной сессии не создают такую утечку. Игроки имеют равный суммарный вес при обучении. Повторяющиеся окна и противоречивые метки внутри сессии отклоняются. Если в части нет обоих классов, соберите больше разнообразных игроков; не подбирайте seed ради красивой тестовой метрики.

Для каждой из 48 колонок окна считаются 6 агрегатов: mean, std, p10, median, p90, abs-max. Получается **288 входов модели**, затем стандартизация и логистическая регрессия. Схема, названия колонок и их порядок сохраняются в JSON модели и проверяются при загрузке. Стандартизация обучается только на train. Порог выбирается на calibration по максимальной оценке честных записей каждого игрока: хотя бы одно превышение считается ложной тревогой этого игрока. `--target-fpr` задаёт цель на калибровке, **не гарантию** на новых игроках. API сохраняет совместимое поле `confidence` (0–100), но это оценка модели, **не калиброванная вероятность вины**. Плагин использует порог модели и накопительный буфер.

JSON модели содержит параметры, контрольную сумму данных, распределение игроков и отчёты calibration/test: recall, ложные тревоги на окна и игроков. Готовый файл не перезаписывается: используйте версионные имена. Не меняйте модель по результатам финальной выборки снова и снова: она перестанет быть независимой. Для сравнения следующих моделей резервируйте новые данные. Метрики модели не являются проверкой всей системы наказаний/буфера.

Ноль ложных тревог на маленькой выборке ничего не гарантирует: отчёт показывает одностороннюю 95% верхнюю границу риска при нуле ошибок. Даже при независимых представительных наблюдениях для границы около 0.1% нужно примерно 3000 честных игроков в **тестовой** части. Непредставительные данные не исправляются большим количеством похожих окон.

Остановите API и запустите явно выбранную модель:

```bash
bash start-backend.sh --model backend/models/aim-v2.json
```

Проверяйте `GET /health` → `ready=true`, затем изучайте оценки и реальные ложные тревоги в режиме `ai.observe-only: true`. Без готовой модели/при ошибках API плагин сбрасывает накопление и уменьшение урона; запрос ограничен 5 секундами и одним активным предсказанием на игрока. Не включайте наказания по синтетическим тестам. После проверки на реальных отложенных данных и живого наблюдения можно отдельно включить `ai.observe-only: false` и нужное действие в серверной конфигурации, перезапустив сервер. Никакого «ноль фолсов» этот проект не обещает.

## Тесты разработки

```bash
bash start-backend.sh --test
```

Тесты проверяют обучение, разбиение без общих игроков, отказ при плохих данных, HTTP-аутентификацию, отсутствие модели, бинарный формат и предсказания. Синтетические данные создаются во временном каталоге и не превращаются в рабочую модель.

Для полной проверки совместимости с существующим Java-сериализатором после сборки плагина:

```bash
mkdir -p /tmp/anguard-fixture
javac -cp build/libs/SilentAC-3.0.jar -d /tmp/anguard-fixture backend/tests/FlatBufferFixture.java
java -cp /tmp/anguard-fixture:build/libs/SilentAC-3.0.jar FlatBufferFixture /tmp/anguard-fixture/window.bin
ANGUARD_JAVA_FIXTURE=/tmp/anguard-fixture/window.bin bash start-backend.sh --test
```

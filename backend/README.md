# Обучение AnGuard: первая проверяемая модель

Этот модуль обучает базовую логистическую модель для **aim/rotation**, а не универсальный детектор всех читов. Нейросеть, готовый датасет и подтверждённое качество здесь не поставляются. Сначала собирайте данные на контролируемом тестовом Paper 1.21.4 сервере с ProtocolLib. Участники должны знать о записи; UUID в файлах — идентификаторы игроков, не публикуйте сырые записи и ключи.

## Установка и безопасный запуск

Из любой папки, где вы хотите разместить проект:

```bash
git clone https://github.com/MigosHack/AnGuard.git
cd AnGuard
bash start-backend.sh
```

Если изменения пока находятся в ветке `work`, клонируйте с `git clone -b work https://github.com/MigosHack/AnGuard.git`.

Один скрипт создаёт `backend/.venv`, устанавливает закреплённые зависимости и запускает API. На Debian/Ubuntu при отсутствии Python/venv он устанавливает их через apt (нужны root или sudo); на других системах нужен Python 3.10–3.13 с venv. Для самого бэкенда Java не нужна. Повторный запуск переиспользует окружение и ключ. Путь к проекту может быть любым, включая пробелы; скрипт можно вызывать из другой директории. Для остановки нажмите Ctrl+C.

```bash
bash start-backend.sh --port 8000
bash start-backend.sh --model backend/models/aim-v1.json
bash start-backend.sh --install-only
bash start-backend.sh --test
```

Без `--model` API запускается без модели: это позволяет подготовить сервер до сбора данных, но предсказания ещё недоступны. Пути к модели и данным задаются относительно текущей папки shell. Если порт занят, выберите другой через `--port` и измените `vds.port` плагина.

Сервер слушает только loopback:8000. `local.py` создаёт случайный ключ с правами 0600 в игнорируемом `backend/.local/api-key`; не выводит его. При заданном `ANGUARD_API_KEY` использует его вместо локального файла. Не используйте публичный ключ из старого config.yml.

Перед запуском Minecraft задайте **тот же** ключ в окружении процесса Java. Например, для локально созданного ключа в shell, из корня репозитория:

```bash
export ANGUARD_API_KEY="$(cat backend/.local/api-key)"
# Затем запустите свой Paper-сервер из этой shell с JDK 21.
```

Не включайте shell tracing (`set -x`) и не печатайте переменную. Разместите собранный `build/libs/anguardai-3.0.jar` и `libs/ProtocolLib.jar` в каталоге plugins вашего Paper-сервера. Адрес API задаётся в **сгенерированном сервером** `plugins/AnGuard/config.yml`: `vds.ip: 127.0.0.1`, `vds.port: 8000`. Ключ из переменной окружения имеет приоритет перед `vds.secret_key`. Существующим установкам нужно явно добавить `ai.observe-only: true`, отключить `autoban.enable` и `ai.damage-reduction.enabled`; пакетные значения конфигурации не перезаписывают старый файл.

Plain HTTP поддерживается только на одной машине через loopback. Для удалённого API сначала требуется отдельная настройка TLS-транспорта; не пересылайте этот ключ по открытой сети.

`GET /health` без модели возвращает `status=ok, ready=false`. Запросы предсказания без модели получают 503, а не выдуманную оценку. Сервер предназначен для локальной разработки; пропускную способность под вашей нагрузкой нужно измерять отдельно.

## Сбор данных

В игре или серверной консоли, с правом `anguard.admin`:

```text
/anguard record PlayerName legit
/anguard stop PlayerName
/anguard record PlayerName cheat
/anguard stop PlayerName
```

Метка задаётся администратором **по известным условиям эксперимента**, никогда по оценке модели. `cheat` записывайте только в изолированном тесте с заранее известным включённым aim-читом; `legit` — с проверенным чистым клиентом. Старт новой записи создаёт новую сессию и сбрасывает окно; выход игрока прекращает запись. Во время записи игрок не наказывается этой проверкой, даже если позже вы включите наказания.

Файлы: `plugins/AnGuard/training/windows-<uuid>.jsonl`. Схема v1: 40 **сэмплов вращения** (не гарантированно 40 серверных тиков), по 8 чисел: deltaYaw, deltaPitch, accelYaw, accelPitch, **jerkPitch, jerkYaw**, gcdErrorYaw, gcdErrorPitch. Хранятся UUID игрока/сессии, метка и время. Порядок jerk-полей совпадает с существующим FlatBuffers форматом. Файловая запись вынесена в отдельный поток с ограниченной очередью; при переполнении окна отбрасываются с предупреждением. Следите за размером файлов и свободным местом, запись сама по таймеру не прекращается.

Окна после телепорта исключаются; при ping >200 мс или TPS <18 запись и применение оценки пропускаются. Это базовые предохранители, не доказательство защиты от всех сетевых артефактов.

Соберите разные чувствительности мыши, FPS, стили PvP и уровни навыка, включая сильных честных игроков. Разделите тесты по типам и настройкам aim-читов. Не используйте один UUID для всех участников. Минимум инструмента — 15 разных игроков с обоими классами в каждой части; для достоверных выводов нужно значительно больше. Скопируйте файлы в игнорируемый `backend/recordings/`.

## Обучение и проверка

```bash
bash start-backend.sh --train \
  backend/recordings/*.jsonl --output backend/models/aim-v1.json \
  --target-fpr 0.001
```

Игроки делятся 60/20/20 на обучение, калибровку порога и финальную проверку. Ни один UUID не попадает в разные части, поэтому перекрывающиеся окна одной сессии не создают такую утечку. Игроки имеют равный суммарный вес при обучении. Повторяющиеся окна и противоречивые метки внутри сессии отклоняются. Если в части нет обоих классов, соберите больше разнообразных игроков; не подбирайте seed ради красивой тестовой метрики.

48 агрегатов движения → стандартизация → логистическая регрессия. Стандартизация обучается только на train. Порог выбирается на calibration по максимальной оценке честных записей каждого игрока: хотя бы одно превышение считается ложной тревогой этого игрока. `--target-fpr` задаёт цель на калибровке, **не гарантию** на новых игроках. API сохраняет совместимое поле `confidence` (0–100), но это оценка модели, **не калиброванная вероятность вины**. Плагин использует порог модели и накопительный буфер.

JSON модели содержит параметры, контрольную сумму данных, распределение игроков и отчёты calibration/test: recall, ложные тревоги на окна и игроков. Готовый файл не перезаписывается: используйте версионные имена. Не меняйте модель по результатам финальной выборки снова и снова: она перестанет быть независимой. Для сравнения следующих моделей резервируйте новые данные. Метрики модели не являются проверкой всей системы наказаний/буфера.

Ноль ложных тревог на маленькой выборке ничего не гарантирует: отчёт показывает одностороннюю 95% верхнюю границу риска при нуле ошибок. Даже при независимых представительных наблюдениях для границы около 0.1% нужно примерно 3000 честных игроков в **тестовой** части. Непредставительные данные не исправляются большим количеством похожих окон.

Остановите API и запустите явно выбранную модель:

```bash
bash start-backend.sh --model backend/models/aim-v1.json
```

Проверяйте `GET /health` → `ready=true`, затем изучайте оценки и реальные ложные тревоги в режиме `ai.observe-only: true`. Без готовой модели/при ошибках API плагин сбрасывает накопление и уменьшение урона; запрос ограничен 5 секундами и одним активным предсказанием на игрока. Не включайте наказания по синтетическим тестам. После проверки на реальных отложенных данных и живого наблюдения можно отдельно включить `ai.observe-only: false` и нужное действие в серверной конфигурации, перезапустив сервер. Никакого «ноль фолсов» этот проект не обещает.

## Тесты разработки

```bash
bash start-backend.sh --test
```

Тесты проверяют обучение, разбиение без общих игроков, отказ при плохих данных, HTTP-аутентификацию, отсутствие модели, бинарный формат и предсказания. Синтетические данные создаются во временном каталоге и не превращаются в рабочую модель.

Для полной проверки совместимости с существующим Java-сериализатором после сборки плагина:

```bash
mkdir -p /tmp/anguard-fixture
javac -cp build/libs/anguardai-3.0.jar -d /tmp/anguard-fixture backend/tests/FlatBufferFixture.java
java -cp /tmp/anguard-fixture:build/libs/anguardai-3.0.jar FlatBufferFixture /tmp/anguard-fixture/window.bin
ANGUARD_JAVA_FIXTURE=/tmp/anguard-fixture/window.bin bash start-backend.sh --test
```
